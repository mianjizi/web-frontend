**M8-2（单选）** `[M8][§3.2][理解][★★][2 分]`
关于幂等性，下列说法正确的是：
A. 幂等性只与返回码有关，返回码相同就说明幂等
B. `DELETE` 会改变状态，因此不是幂等方法
C. 幂等指「执行一次与执行多次，服务端最终状态相同」；`PUT` 幂等而 `PATCH` 不一定，这直接决定某操作能否自动重试
D. `POST` 一旦加上请求体就变成幂等

**M8-3（单选）** `[M8][§3.7][理解][★★][2 分]`
关于 `Cache-Control`，下列说法正确的是：
A. `no-cache` 就是完全不允许缓存
B. `no-cache` 允许存储但每次必须回服务器校验（可能得到 304）；`no-store` 才是彻底不许存
C. `no-store` 允许存储但每次校验
D. `ETag` 比 `Last-Modified` 精度低，所以优先用后者

**M8-4（单选）** `[M8][§3.9][理解][★★][2 分]`
关于 CORS，下列说法正确的是：
A. 只要 `Content-Type` 是 `application/json`，该 `POST` 就走简单请求路径
B. 方法属于 `GET`/`HEAD`/`POST`、请求头都在安全列表内、且 `Content-Type` 只取表单三种时才走简单请求；发 JSON 的 `POST` 必然触发预检
C. 服务端把 `Access-Control-Allow-Origin` 设为 `*` 后，带 Cookie 的跨源请求也一定能成功
D. CORS 是服务端安全机制，`curl` 也会受它约束

**M8-5（单选）** `[M8][§3.10][理解][★★][2 分]`
关于 `fetch` 的失败模型，下列说法正确的是：
A. 接口返回 404 或 500 时，`fetch` 的 Promise 会 reject，进 `catch`
B. 只有网络层失败（DNS 失败、连不上、被 abort、被 CORS 拦下）才 reject；4xx/5xx 是成功完成的通信，必须自己判 `res.ok`
C. `res.ok` 为 `true` 表示状态码一定是 200
D. `AbortError` 属于故障，必须按网络错误上报

**M8-6（单选）** `[M8][§3.5][理解][★★][2 分]`
关于 HTTP 版本演进，下列说法正确的是：
A. HTTP/2 已经多路复用，因此不存在队头阻塞问题
B. HTTP/2 解决的是 HTTP/1.1 的应用层排队问题；它跑在 TCP 上，仍受 TCP 层队头阻塞影响，HTTP/3 换成基于 UDP 的 QUIC 后才做到流之间独立重传

D. HTTP/2 之下仍然需要域名分片来提升并发

## 八、参考答案要点

> 只给**判分要点与关键词**；编程与设计题只给**验收判据、评分要点与常见扣分点**，不给完整代码。

### M6

**M6-1** B。lockfile 记录实际装到的确切版本与整棵依赖树，是可复现的唯一凭据；`node_modules` 与产物目录是可再生产物；`.env` 含本地/敏感配置。判分要点：选 B 得分，仅答「B 更小」不给分。

**M6-2** C。`^` 允许升到不跨主版本的最新版本；`~3.5.43` 才是 3.5.x；写死版本号才锁定单版本。

**M6-3** B。裸模块说明符必须由工具按 `node_modules` 规则解析，并补路径与扩展名。

**M6-4** B。关键词：只注入 `VITE_` 前缀、白名单不是加密、`.env` 不入库。

**M6-5** C。关键词：ESLint 管 bug 风险、Prettier 管排版、Biome 二合一。

**M6-6** B。关键词：逐文件转译看不到跨文件类型关系；必须单独跑 `tsc --noEmit`。

**M6-7** B。关键词：哈希让内容不变的资源可长期缓存；入口 HTML 必须短缓存/不缓存，否则用户拿不到新文件名。

**M6-8** 错。两者命运相反：lockfile 是「可复现」的唯一凭据必须提交；`node_modules` 是可再生产物，体积大、含二进制、跨平台不通用、可能被投毒，绝不能提交。答「都对」或「都错」不给分。

**M6-9** 错。提交历史、缓存、别人的本地克隆、CI 日志里都可能留有副本；正确动作是**立即轮换密钥**，再清理历史。判分关键词：轮换、删除≠撤回。

**M6-10** 四类问题：① 裸模块说明符（`from 'vue'` 浏览器无法解析）；② 非 JS 文件（import `.css`/`.vue`/`.svg`）；③ 较新的语法（旧浏览器上是语法错误，整个模块不执行）；④ 请求数与体积（数百个小文件与远超必需的源码）。每类要有「不解决就失败」的最小例子，缺例子扣一半。

**M6-11** ① dev 期浏览器加载原生 ES 模块、服务器按需编译被请求到的文件，不做整包打包，省掉「每次启动重建全量产物」；② 生产期要打包、压缩、tree-shaking、代码分割、产物哈希，模块合并且加载顺序改变，只有 `preview` 形态才逼近线上。纪律一句：开发看速度，上线看产物。

**M6-12** 转译＝逐文件剥掉类型与语法（快、可并行、可缓存）；类型检查＝校验整个工程的类型关系（慢、全局）。不能合并的原因：逐文件转译看不到另一个文件的类型。检查链四层：类型检查（tsc）管类型自洽 → 代码检查（ESLint）管会不会出错 → 格式化（Prettier）管好不好看 → 测试（Vitest/Playwright）管行为对不对。

**M6-13** 关键词：`any` 关掉检查，错误流到运行时才炸；`unknown` 强制在边界处先收窄再使用，把错误提前到写代码时。要求点明「接收外部数据」这一场景与「编译期 vs 运行时」的对照。只说「any 不好」不给分。

**M6-14** 任答四项即可：依赖图解析（产物里出现你没直接 import 的文件内容）／tree-shaking（整体引入 vs 只引一个函数的体积对比）／代码分割（产物目录多出按路由或动态 import 命名的文件）／产物哈希（改一个字重新构建，文件名变化）／转换与降级（`.scss` 变成产物 `.css`）。每项都要有产物层面的观察点。

**M6-15** 根因：`.js` 未声明 `"type": "module"` 时按 CJS 解析，`import` 语法不合法。三种改法：① `package.json` 加 `"type": "module"`；② 文件改名 `.mjs`；③ 改用 CJS 的 `require`。边界：会触到「ESM 能 `import` CJS、CJS 不能同步 `require` ESM」这条边界的是改法 **①②**——它们把 `main.js` 变成 ESM，去 `import` 一个 CJS 依赖（`util.cjs`），正落在边界允许的一侧（ESM→CJS）；改法 ③ 两端都留在 CJS（CJS `require` 一个 CJS 模块），不涉及 ESM/CJS 互操作，故不触及该边界。

**M6-16** ① `unknown` 在使用前必须先收窄（类型守卫、`in`/`typeof`/字面量判断），`any` 直接放弃检查；② 需补收窄分支，并在分支内使用收窄后的类型；③ `any` 版本在运行时若形状不符会直接抛错且无编译期提示，`unknown` 版本把错误挡在编译期。判分要点：必须区分「编译期拦下」与「运行时才炸」。

**M6-17** ① 错处：`vitest` 放进了 `dependencies`（它只在你写代码、检查、测试与构建时出现，不参与前端产物，应为 `devDependencies`）；后果是别人执行 `npm i --production` 时会白装工具链。`vue`/`pinia` 放 `dependencies` 正确（会被打进给用户的前端产物）。② `.gitignore` 至少四类：`node_modules`；构建产物目录与构建缓存/测试产物/本地日志；`.env*`（提交 `.env.example` 交代变量名）；本地证书与含敏感信息的编辑器配置。判分要点：必须给出「会不会被打进前端产物」这条判据，只答结论不给分。

**M6-18（编程·只给验收判据与评分要点）**
验收判据：① 不打包直接加载失败、加载你的产物成功，且行为与手工按顺序执行等价（有对照数据）；② 模块表中每个模块只出现一次，循环引用不死循环、不栈溢出；③ 产物是单文件、不依赖任何外部运行库；④ `README.md` 写清：裸说明符/路径解析、作用域与导出的承载方式、依赖加载顺序、为什么浏览器单独做不到，并列出至少两处你的实现做不到的事。
评分要点：能跑通且行为一致 35 分；循环引用处理正确 20 分；脚本结构可读、有注释 15 分；`README.md` 说明的具体程度 20 分；不违反「不得引入打包库」10 分。
常见扣分点：引入现成打包库完成打包（按零分处理）；只处理单向 import；产物需要额外加载器；`README` 只抄概念无自己的对照；脚本超过复杂度上限且无注释。

### M7

**M7-1** C。关键词：Vue 代理追踪读写、细粒度；React 引用比较、必须换新对象。

**M7-2** D。在渲染函数里发请求本身就是误区，且并不能消除竞态。

**M7-3** A。三次回调读到的是同一个渲染闭包中的旧值；要用函数式更新 `setCount(c => c + 1)` 才能得到 +3。

**M7-4** C。key 是列表项的稳定身份；只需在同一父节点的兄弟间唯一；随机数 key 等于每轮全部重建。

**M7-5** C。同一份数据存两份就有两个真相，必然不一致；应用派生值而不是复制。判分要点：能指出「两份真相」。

**M7-6** C。只在单页使用的筛选关键词应放页面局部状态或路由查询参数。判分要点：能用「共享范围与生命周期」说理。

**M7-7** B。判据一句话：算出一个值用 computed，因为值变了去做事用 watch。computed 里不能发请求（可能是多次求值且属副作用）。

**M7-8** B。关键词：props 向下、事件向上、数据的所有者负责修改。

**M7-9** B。关键词：同一路由仅参数变化时组件实例被复用；取数的依赖应是「参数」而不是「挂载」。

**M7-10** 错。computed 应是纯计算、可能在渲染中被多次求值；发请求属副作用，放 watch 或事件处理里。答「对」不给分。

**M7-11** 错。props 每次都是新引用时比较必然失败，白付比较成本；应先稳定引用或用更细的订阅，且要先测量再优化。

**M7-12** 错。空态要明确告诉用户「这里确实没有内容」并给出下一步动作，加载态要给进度感；两者视觉上必须可区分。

**M7-13** 三句话：数据只能从父组件往下传（props）；子组件不改 props；子组件通过事件/回调把意图上报，由数据所有者执行修改。删除操作：子组件 emit 一个带 id 的事件，父组件收到后 filter 掉该项。

**M7-14** 索引是位置而不是身份；前插后第 n 项的索引对应到了另一条数据。可观察现象：带输入框的列表前插一行时，输入内容跟着位置错位（或动画/局部状态张冠李戴）。勉强可接受的条件：只追加、不重排、不删除、每项没有内部状态。

**M7-15** 三个信号：① 相距很远的组件要用同一份数据；② 这份数据要在路由跳转之间存活；③ 多个组件都要改它，且改动逻辑最好集中管理。反例各一：只在单页使用的筛选条件（放路由查询参数或页面局部状态）；弹窗开关；输入草稿（放组件内部）。

**M7-16** 成立：日常视图同步不必手写 DOM 操作。错误：测量元素尺寸（`getBoundingClientRect`）、管理焦点（`focus()`）、集成需要真实节点的第三方库、ref 转发，仍是必要操作，且应放在副作用/生命周期里。判分要点：两边各要有具体场景。

**M7-17** 解构取到的是**当时的普通值**，脱离了代理的读写追踪。修法：① 用 `toRefs(state)` 解构；② 干脆用 `ref`（读时 `.value`）；或直接访问 `state.keyword`。

**M7-18** Vue 用 `Proxy` 包裹对象，读时记依赖、写时通知用到它的地方（细粒度追踪），所以直接改属性有效；React 不追踪写操作，每次让组件函数重跑得到新树，靠引用比较判断「变了没有」，所以必须用新对象替换旧对象（这也是其并发调度得以成立的前提）。关键改动：Vue 侧可直接改第 3 项字段；React 侧要对数组做 `map` 生成新数组后 setState。判分要点：必须出现「代理追踪」「引用比较」这类机制层面的词。

**M7-19** composable 内部可以使用 `ref`、`computed`、生命周期钩子，因此它有自己的响应式状态与挂载/卸载时机；普通工具函数不能。只有 composable 才能做的事举例：在内部 `onMounted` 注册监听并在 `onUnmounted` 对称清理，或返回一份随输入自动更新的派生状态。

**M7-20** 四态：加载中 / 成功（有数据）/ 成功但为空 / 失败。区分的理由：只写前两种时，「空列表」看起来像「还在加载」，「失败」看起来像「永远转圈」。消除竞态的做法（任答一种）：作废标记（stale flag）+ 清理函数；`AbortController` 中断上一次请求；请求序号只接受最新一次的结果。

**M7-21** 原因：`reactive` 解构脱离了代理，读到的是普通值，改它不再触发更新。修法一：改回 `state.keyword` / `state.list` 直接访问；修法二：用 `toRefs(state)` 解构，或整体改用 `ref`。

**M7-22** ① 依赖数组为空，`id` 变化不重新取数（应把 `id` 放进依赖）；② 缺少清理，快速切换时旧响应会覆盖新结果，且可能对已卸载组件 setState（应在清理里作废：stale 标记或 `AbortController`）。可加分：列表渲染缺 `key`；未判 `res.ok`（关联 M8）。

**M7-23** 根因：`list.push` 改的是同一个数组引用，React 用引用比较认定「没变」，不触发重渲染（或时好时坏）。改动：`setList([...list, item])`，或在依赖旧值时用函数式更新 `setList(prev => [...prev, item])`。与浅拷贝的区别：浅拷贝产生新数组但内层对象仍是同一引用，深层修改同样不会被认为变化，还会影响其它持有该对象的组件。

**M7-24** 问题：用数组索引当 key；另有 `onPick` 每次渲染都是新函数，会让子组件比较失效。现象：列表前插或重排时组件状态错位（输入内容串行、高亮错位、动画播错元素）。修法：`key={row.id}` 用随数据走的业务 id；`onPick` 用 `useCallback` 稳定引用或改由子组件自行取用。

**M7-25（编程·只给验收判据与评分要点）**
验收判据：① 抽出的函数不依赖任何具体组件，输入是数据源与筛选条件，输出是筛选结果与计数；② 至少两个组件通过它取得同一份派生结果，改一个筛选条件后摘要与列表行数同步变化；③ 组件代码中不再出现重复的 filter 表达式（可全文搜索验证）；④ Vitest 单测覆盖「组合筛选」与「空结果」两个用例并全部通过。
评分要点：契约清晰 30 分；复用彻底 30 分；行为正确 25 分；测试与命名规范 15 分。
常见扣分点：抽出的函数内部仍 new 了一份状态；两个组件各写一份 filter 表达式；测试只断言「不抛错」；命名不带 `use` 前缀。

**M7-26（编程·只给验收判据与评分要点）**
验收判据：① 直接访问 `/items/:id` 能正确渲染（刷新不丢）；② 从详情 A 直接切到详情 B 时数据会重新获取；③ 断网显示错误态且重试有效，空数据显示空态，两者与加载态可区分；④ 未登录被守卫拦到登录页，登录后回到原目标。

### M8

**M8-1** C。A 把 301/302 对调；B 把 304 当错误；D 混淆客户端错误与服务端错误（502 是网关从上游收到无效响应）。

**M8-2** C。关键词：执行一次与执行多次服务端最终状态相同；`PUT` 整体替换幂等、`PATCH` 局部补丁不幂等；幂等决定能否自动重试。可加分：幂等 ≠ 安全（`DELETE` 幂等但改状态）。

**M8-3** B。`no-cache` 名字骗人：可以存但每次必须校验；`no-store` 连存都不许。`ETag` 基于内容指纹，比 `Last-Modified` 更受推荐。

**M8-4** B。`application/json` 不在简单请求的 `Content-Type` 白名单内；带 Cookie 时 `Allow-Origin: *` 不生效，必须回显具体来源并加 `Allow-Credentials: true`；CORS 只在浏览器生效。

**M8-5** B。关键词：只有拿不到回答才算网络错误；拿到了回答（哪怕 500）都是要自己判的业务结果。`res.ok` 是 200–299；`AbortError` 不是故障，需与用户主动取消区分。

**M8-6** B。HTTP/2 解决应用层排队（多路复用、二进制分帧、头部压缩）；TCP 层队头阻塞留给 HTTP/3（基于 QUIC 的 UDP，流级独立重传、连接迁移、强制加密）。HTTP/2 之下域名分片不再需要且有害。

**M8-7** 对。`SameSite=None` 必须同时 `Secure`，否则浏览器拒绝写入该 Cookie；现象就是「服务端 Set-Cookie 了，前端却一直未登录」。判分要点：必须点出「浏览器拒收」与「Secure 缺失」两处。

**M8-8** 必须指出 `POST` 非幂等、盲目重试可能产生重复订单；给出幂等键（客户端生成的唯一标识随请求携带、服务端据此去重）或「先查询再决定」的补偿思路。参考流程：不自动重试 → 用同一幂等键查询或重发 → 服务端按幂等键去重 → 有明确失败才提示用户。答「重试三次就好了」不给分。

**M8-9** 排查步骤：先按 XHR/Fetch 过滤找那条 `OPTIONS` 预检 → 逐行读它的请求头（`Access-Control-Request-Method`、`Access-Control-Request-Headers`）与响应头 → 找到缺失的 `Access-Control-Allow-*` → 补齐后重发，看真正的 `POST` 是否成功。服务端清单：`Access-Control-Allow-Origin`（回显具体来源，此时不能用 `*`）、`Access-Control-Allow-Methods: POST`、`Access-Control-Allow-Headers: content-type`、`Access-Control-Allow-Credentials: true`（可选 `Access-Control-Max-Age`）。前端需带 `credentials`。带凭据时通配来源被规范禁止。

**M8-10** 成因：入口被强缓存 → 用户拿到旧 HTML → 旧 HTML 引用的哈希资源名在新版本已被删除 → 白屏。正确组合：入口 `no-cache` + `ETag` 走协商缓存；静态资源长 `max-age`（配内容哈希，可选 `immutable`）。答「让用户强刷」不给分。

**M8-11** 风险链路：第三方依赖被入侵 → 同页任意脚本可一行 `localStorage.getItem` 读走令牌并外传 → 攻击者以用户身份调用接口；刷新令牌寿命长、权限大，等于长期失守。更稳方案：刷新令牌放 `HttpOnly` + `Secure` + `SameSite` 的 Cookie（JS 读不到），访问令牌短期且仅存内存。CSRF 补偿：`SameSite` 限制跨站携带 + 服务端做 CSRF 校验（自定义头或双提交令牌）。只答「localStorage 不安全」不给分。

**M8-12** 问题：`encodeURI` **不会**编码 `&`、`=`、`+`、`/` 等字符，参数值中一旦含这些字符就会破坏查询结构。正确写法：`encodeURIComponent(keyword)`，或用 `URLSearchParams` 统一编码。被掩盖的差异：空格在路径里常写作 `%20`、在 `application/x-www-form-urlencoded` 的查询串里常写作 `+`，两种上下文约定容易被忽略。

**M8-13** 任答三点即满分：① 未判 `res.ok`（4xx/5xx 不会 reject，必须自己判）；② 未编码 `id`（应 `encodeURIComponent`，含特殊字符会破坏路径）；③ 未检查 `Content-Type` 就直接 `json()`（会得到解析错误）；④ 无超时与取消（卸载后无法中止）；⑤ 无错误分类与可读信息。判分要点：第一点是硬门槛。

**M8-14** ① 慢在被限制的并发上：`Queueing + Stalled` 占了 1.47 s，而 TTFB 只有 240 ms、下载 35 ms；这说明不是服务端慢、也不是带宽问题，而是请求在排队或等可用连接。② 先动并发与优先级：减少首屏并发数、把关键请求提前、避免一次发几百个请求打满连接池（可结合代码分割与懒加载）。③ 结论会变化：同样 1.47 s 若出现在 TTFB，则是服务端处理或网关排队慢，方向转为查后端与数据源、加缓存，而不是调前端并发。

**M8-15（编程·只给验收判据与评分要点）**
验收判据：① 单测中 404 命中「业务错误」分支而**不**命中网络错误分支；② 超时后能断言底层信号已中止，而不只是 Promise 提前结束；③ 取消路径抛出可识别的取消错误，且不被当成故障上报；④ 非 JSON 响应给出可读错误。
评分要点：失败模型正确性 25 分（硬门槛，此项为零则整题不及格）；超时真中止 25 分；取消路径识别 20 分；非 JSON 处理 15 分；测试覆盖与命名 15 分。

**M8-16（设计·只给验收判据与评分要点）**
验收判据：① 三个需求各选一个方案，每个选择给出两条论据与一条代价；② 每条论据都能落到教案 §3.11 对比表的某一列，不出现「更先进所以用它」这类理由；③ 所选方案写清断线处理（重连间隔、心跳、是否需要消息补发）；④ 其中一个方案被真正实现并演示不断线重连。
参考选择：① 站内通知 → SSE 优先（单向、走 HTTP、自带重连、与现有鉴权/代理兼容；代价是单向与 HTTP/1.1 下同域连接数限制）；② 进度百分比 → SSE（单向流、文本够用）；③ 协同编辑 → WebSocket（双向、低延迟；代价是心跳保活、重连与消息补发、服务端必须自校验 `Origin` 并鉴权）。长轮询在频率低且设施老旧时也可接受。
评分要点：论据质量 40 分；代价具体性 25 分；断线处理设计 20 分；实现在报告中的证据 15 分。

评分要点：覆盖真实用户路径 35 分；失败可定位（截图/trace）25 分；CI 门禁接线正确 30 分；命名与提交规范 10 分。
常见扣分点：用 CSS 类名当选择器导致一改样式就崩（应优先按角色/文本定位）；测试依赖真实网络或执行顺序；只写断言不写等待条件造成偶发红；门禁只跑测试不跑 lint。

**M9-20（编程·只给验收判据与评分要点）**
验收判据：① 公网链接可访问；② 直接访问/刷新深层路由不 404（回退已配）；③ **手机蜂窝数据下**（非本机 Wi-Fi）刷新深层路由不 404，并有截图；④ 能演示一次回滚（把线上切回上一版）；⑤ 前端产物里搜不到任何密钥。
评分要点：SPA 回退正确 30 分；手机非本机网络验证 30 分（仅本机截图不给分）；回滚与监控 25 分；上线检查清单勾选完整 15 分。
常见扣分点：从没跑过 `preview` 就上线，产物路径全 404；把 API key 写进前端 `.env`；用本机 Wi-Fi 截图冒充真机验证；只发一版、不留旧产物，无法回滚。

### M10

**M10-1** B。A 要按配置与页面确认；C 取决于服务器与数据源（SSR 不保证更快）；D 增量更新只是窗口内复用或按需重建，不是实时。

**M10-2** B。它标的是边界：该组件在服务端也要参与产出 HTML，同时其代码要下发到浏览器以完成水合；被标记的文件及其 import 的依赖都会下发。

**M10-3** B。Nuxt 3 已 EOL，配置与目录与 4.x 线有差异，应按 Nuxt 4.5.2 官方文档建项目；A、C、D 都错。

**M10-4** C。WASM 靠「已有原生代码复用」或「确有 CPU 密集负载并能测出收益」来判；跨边界传数据有开销、DOM 访问仍需经过 JS；WASM 与自定义元素都可以与框架共存；WebGPU 各浏览器与平台支持程度不一致，课程只做定性介绍。

**M10-5** 错。省了网络往返，但边缘运行时可用 API 是受限子集、冷启动/内存/执行时长有上限，常常不能像常驻服务那样连数据库（长连接、原生模块可能不可用），可观测与调试工具不同、排错更难；而且「数据在哪里」与「逻辑有多重」同样决定结果。

**M10-6** 因为服务端产出的 HTML 只有样子、不含事件与状态（只有结构、样式）；浏览器要下载并执行组件代码把这批静态 DOM 认领过来、绑定监听，这段过程是水合，水合完成前页面「看得见但点不动」。减少等待的手段（任写两条）：只给需要交互的区块下发脚本（局部水合）、岛屿架构、Streaming SSR 先发已就绪部分、减小客户端包体。判分要点：要出现「水合」或等价机制描述，且手段要具体。

**M10-7** 建议：内容因人而异，不能进共享缓存走静态产物；但这是内部工具——用户固定、SEO 无意义、访问量有限，缺的是权限、表单与审批流而不是首屏指标，因此**优先 SPA + 静态托管 + 接口鉴权**，不引入元框架；若确需首屏体验，可对登录后的个性化面板用 SSR 并注意个性化数据不得进共享缓存。退出成本一句：应落到具体判断，如「路由与构建层能否替换、状态与数据能否导出、约定有多深」，例如「若将来要换成元框架，现有 SPA 的路由层与数据层可原样保留，代价主要是重新组织数据获取与目录约定」。

**M10-8** ① 会带。依赖会顺着客户端边界进入浏览器包：`Chart` 标了 `'use client'`，它 import 的图表库随边界下发（服务端组件能渲染客户端组件，但客户端组件的依赖都会被带进包）。② 可行做法：把重依赖留在服务端（只在服务端渲染需要它的部分）、把客户端组件切到最小交互壳、对该依赖做延迟加载（动态 import），最根本的是把它挡在客户端边界之外。③ 验证办法：构建后对比加/不加该依赖的产物体积、Network 面板看下发了哪些 chunk。

**M10-9（编程·只给验收判据与评分要点）**
验收判据：① 三页 build 后能从产物目录打开，且正文在 HTML 中（可用 `curl` 验证）；② 列表页不少于 10 条数据，详情页路由参数正确；③ 至少一页含一处交互且行为正常；④ `README.md` 写明所用版本、命令，以及一段「选型理由 + 退出成本」；⑤ 未提交 AI 生成的完整答案，若有 AI 参与须说明范围与自己的修改。
评分要点：可构建可运行 30 分；页面与路由正确 25 分；交互可用 15 分；README 的版本与理由 20 分；诚信说明 10 分。
常见扣分点：使用 Nuxt 3（版本口径不符，按未完成处理）；用 `curl` 抓到的 HTML 里没有正文（说明没真正产出静态 HTML）；只交代码不写选型与退出成本；README 里版本号写成课程口径之外的值；AI 参与但未说明。

**M10-10（编程·只给验收判据与评分要点）**
验收判据：① 项目可 typecheck 与 lint；② 能说明所找到的依赖 `os`/`cpu` 字段的含义；③ 能说明「为什么在 CI 的 Linux 上装出来可能不同」；④ 写出对「更快的工具是否应立刻替换现有工具链」的判断并给出依据。
评分要点：环境与命令准确 30 分；锁文件字段解释正确 30 分；平台差异解释 25 分；判断题有依据 15 分。
常见扣分点：不提交 lockfile 或未找到平台包就编一个；把 `os`/`cpu` 字段解释成版本号；判断题只答「更快就换」而不提规则覆盖、插件生态与迁移成本。

## 九、易错题与阅卷提示

1. **「能跑」不等于「懂了」——用框架写出来却说不清为什么这样写，必须扣分。**
   这是本课程最典型的失分场景：M7 的编程题、M9 的实验报告里都常见。判分口径：代码能跑只拿功能分；凡要求学生解释设计决策的位置（如为什么这里用 `useMemo`、为什么这个状态放全局、为什么这里要 `key={id}`），若学生只能复述「教程都这么写」「加了感觉快」，则该处**解释分全扣，功能分照给**；若同一份提交里超过三处解释说不出机制，整题按「未理解」处理（不超过 60% 的分）。追问时用一句判据卡：**「如果我不写这一行，会发生什么？」** 答不出即坐实。

2. **「能跑但违反不可变更新」——运行结果对，仍按错误处理。**
   React 侧出现 `list.push(...)` 后 `setList(list)`、`state.obj.x = 1` 后 setter、或对深层对象只做浅拷贝却修改内层：即使当前数据规模下界面「碰巧」更新了，也按**数据流错误**扣分（M7 编程题的响应式与单向数据流项按 0 计）。理由：这类写法在数据规模、渲染调度变化后会静默失效，属于把 bug 藏起来。判法：让学生把列表项数调大或连续操作两次，再看是否一致。Vue 侧对称的错误是**解构 `reactive` 后继续期待响应式**，同样按错误处理（合法的替代是 `toRefs` 或改用 `ref`）。

3. **用 `any` / `@ts-ignore` / 关掉 `strict` / `!important` 让报错消失，一律视为未解决。**
   M6 的实验三与编程题明确写了这条：凡用逃逸手段让 `tsc --noEmit` 或检查器闭嘴的，该题按**未完成**处理，而不是「通过了」。阅卷时要求提交 `git diff` 或最终代码里搜不到 `any`、`@ts-ignore`、`strict: false`。例外只有一种：能说明该处为何必须逃逸、并写明「如果类型错了会在哪一行炸」——此时按半分给。

4. **只交总分截图，不交「改了哪一行 + 为什么影响该指标」，性能题判未完成。**
   M9 的实验一与 M9-10、M9-12 都对着这条。合格的证据链是**同一条件下前后两次测量 + 一行 diff + 一句机制说明**；只说「从 60 提到 92」不给分。反向情况也要会判：指标没变好但学生能说明「为什么没变好、下一步该测什么」，同样给分——这正是课程要的测量纪律。

5. **M8 里把 4xx/5xx 当网络错误，是硬门槛，错则整题不及格。**
   阅卷时先看请求封装里有没有 `if (!res.ok)`：没有则 M8-15 直接判不及格，M8-13 的对应点也不给分。同类高频误判：把 304 当请求失败、把 303/307 记反、把 `AbortError` 按故障上报、把 CORS 报错当成「前端写错了」而不去看那条 `OPTIONS` 的响应头。凡「配了 CORS 头就好了」这种不给具体缺失头名的答案，一律不给分。

6. **提交 `node_modules` 或 `.env` 的，该部分直接不得分，完成补救后才评。**
   补救动作要完整：删掉文件、写入 `.gitignore`、**并说明密钥一旦推上去就等于泄露必须立即轮换**（删文件不等于撤回）。只删文件不讲轮换的，扣该部分的解释分。反过来，把 lockfile 加进 `.gitignore` 的，按「破坏可复现」扣分并说明理由。

7. **版本号与出处写错，按规范问题扣分，不按「笔误」放过。**
   全册只用第八节前「版本口径」列出的版本号；出现 Vue 4、Nuxt 3、或自行编造的版本，扣该题分值。引用资料还须按四级分级判断：把博客、问答、AI 生成内容当依据的，按规范问题扣分；引用规范时把 Living Standard 与 W3C 带状态字段的规范混为一谈、或把已 EOL 的 Nuxt 3 教程当现行口径的，同样扣分。**日期与人名一律不要求记忆，凡出现学生自己编造的年份/人名/论文名/标准编号，本题按零分处理。**

8. **实时通道选型：只给结论不给论据不计分，「更先进所以用它」按零分论。**
   M8-16 与学生作业里最常见。每条论据都要能落到教案 §3.11 对比表的某一列（方向、频率、延迟要求、代价），且必须写出**一条代价**。默认全选 WebSocket、写了 `onmessage` 却无 `onclose` 重连与心跳、把 `Origin` 当唯一鉴权手段，分别扣对应项。

9. **可访问性题不接受「看着像对的」作为结论。**
   M9-14、M9-16 的判分口径：`<div onclick>` 冒充按钮必须指出「键盘不可用」并给出 `<button>` 改法；`alt="图片"`、`outline: none` 一律扣分；给所有元素乱加 `role` 同样扣分（用了半套 ARIA 比不用更糟）。凡声称「已可访问」但拿不出键盘走通或屏幕阅读器验证记录的，该项按未完成处理。

10. **覆盖率数字不作为质量证据；「恒真断言」的测试按没写处理。**
    M9-6、M9-17、M9-18 都对着这条。判法：把被测函数**故意改坏**（改一个比较符、删一个分支），要求至少一条用例变红——变不了红的测试按未写处理，哪怕覆盖率显示 100%。同理，「改坏了但说不清是哪条用例、期望什么、实际什么」的，诊断分不给。

11. **编程与设计题只认验收判据，不认「看起来很像」的成品。**
    手写 bundler（M6-18）引了现成打包库的按零分处理；`useItemFilter`（M7-25）如果两个组件各写一份 filter 表达式，「复用彻底」项不给分；Route 四态（M7-26）若空态与加载态视觉上不可区分，「四态完整」项减半；部署题（M9-20）只用本机 Wi-Fi 截图冒充真机验证的，25 分项不给分。**凡提交的完整实现无法口头解释每一步的，按未理解处理。**

12. **AI 与第三方代码：不标注就按抄袭口径处理。**
    M10 的作业与项目提交里，凡有 AI 参与而未在提交说明写清「哪些是生成的、你改了什么、你怎么验证的」，按把生成内容当自己交付的成果处理（见 [[13-考核方案与评分量规]]）。从网上拷代码不看许可、不标来源的同样扣分。反向提示阅卷：学生主动写出「不确定 + 依据 + 风险」的，**应加分而不是扣分**——这正是本课程要求的表达方式。

13. **路由与参数题：只在挂载时取数的，判「参数变化不重新取数」为关键失分点。**
    M7-9、M7-26 与 M8 的排障题都涉及。判法：从详情 A 直接点进详情 B，看数据是否刷新；只看「刷新页面能打开」不算通过。同类：守卫里写无限重定向（登录页本身也要求登录）、懒加载与预加载混写导致首屏请求变多。

14. **「我这边是好的」不能结案。**
    M8 的排障题与实验报告里，凡以「本地能跑」「同事电脑有问题」作为结论的，**证据分不给**；合格的写法是用 `Copy as cURL` 把请求原样拷给对方复现、用追踪标识对齐服务端日志，并明确区分「浏览器策略层（CORS / 混合内容 / `SameSite` / 缓存）」与「服务端问题」。
