> **工具操作（Windows / Linux）**：本册凡涉及「用工具验证」的题，统一按下面几步做——
> 1. 打开开发者工具：按 **F12**（或 `Ctrl+Shift+I`）；只看控制台用 `Ctrl+Shift+J`（Console）。
> 2. 看请求与缓存：点 **Network** → 按 **F5** 刷新（**先开面板再刷新**，否则抓不到首屏请求）→ 点某条请求，看 **Size** 列写的是 `(disk cache)` / `(memory cache)` 还是真实文件大小；要绕过缓存做对比，按 **Ctrl+Shift+R**（或 `Ctrl+F5`）硬性重载。

> 4. 看「写的 HTML」与「解析后的 DOM」的差别：点 **Elements**（`Ctrl+Shift+C` 可直接点选元素）。
> 5. 查无障碍与结构：**Lighthouse** 面板勾选 Accessibility 后运行；结构校验用 [W3C Nu Html Checker](https://validator.w3.org/nu/)（白名单内的首方校验工具）。

## 七、参考答案要点

> 说明：本节按题号给出**判分要点与关键词**，不提供可直接提交的完整代码。选择题只标答案与解析要点；判断题只标判定与理由要点；简答与分析题给出要点清单与配分方式（"命中几个要点得几分"）；读代码题给出**根因与修复方向**；编程题给出**验收判据、评分要点与常见扣分点**，**绝不给完整代码**。

### M1

**1** 答案 **A**。要点：互联网是网络互联的基础设施（传输层及以下），万维网是跑在其上的应用系统；B 把两者颠倒；C 与事实相反（域名解析、电子邮件不依赖万维网）。答对答案 1 分，能说出"基础设施 vs 应用"1 分。

**2** 答案 **C**。要点：最初的使用者是既要读也要写的研究者，"浏览工具"是后人的窄化。

**3** 答案 **D**。要点：片段（`#` 之后）供浏览器内部跳转，不参与请求；路径、查询串、主机都会出现在请求里。

**4** 答案 **D**。要点：304 = 资源未变、用本地缓存，不是错误；4xx 是客户端错、5xx 是服务端错；500 属服务端错。

**5** 答案 **C**。要点：实现状态与规范状态是两件事，分别查；"规范是 Recommendation"也不等于实现一致。

**6** 答案 **B**。要点：可用它解释／检查，但必须声明使用范围与自证内容，成果自负；"跑通即不用声明""用过即抄袭"都不对。

**7** 答案 **错误**。要点：判据是"'网页打不开'不等于'网络断了'"。万维网只是互联网上的一个应用，域名解析、邮件、文件传输都可能在正常工作；应先分清基础设施层还是应用层的问题（如 4xx 是应用层/服务端响应而非断网）。

**8** 答案 **正确**。要点：`style` 属性是表现层（CSS），写进 HTML 就是把表现混进结构，违反关注点分离；改写方向是移入样式表，外观不变、可维护性变好。**答"违反"但说不出"职责分离"不给分。**

**9** 要点（每点 1 分，满 5 分）：协议 `https`；主机 `example.com`；端口 `8443`；路径 `/docs/page.html`；查询字符串 `?v=2`；片段 `#top`（合计覆盖六个部分）。**哪一部分不发服务器 + 原因**（1 分）：片段不会发出，因为它只用于浏览器内部的文档内跳转，不参与请求报文。

**10** 要点（反驳每条 1.5 分、实验设计 2 分）：反驳理由——① 本地 `file://` 缺少 HTTP 语义（无状态码与响应头，跨域与模块加载受限），很多能力用不了；② 服务器模式才能被他人（同局域网其他设备）访问，即真正的"发布"。实验设计——同一份 HTML 分别用双击打开与经本地静态服务器打开，让他在 Network 面板看不到请求、并试着加载脚本模块／发起跨域请求，自己记录两点差异。

**11** 要点（每点 2 分，满 6 分）：① 规范制定者角度——要求文档严格合法（标签闭合、大小写敏感、属性带引号），一个错就整页解析失败，属于"从纯洁出发"；② 网页作者角度——现实网页大量不合规，严格性把规范推离实践，浏览器为生存继续各写容错逻辑；③ 教训——规范必须贴着现实实现走，否则会被绕过；后来 WHATWG 的 Living Standard 路线把解析器的错误恢复行为写进规范。

**12** 要点（三步核查各 1.5 分，一级资料定义 1.5 分）：核查步骤——① 打开规范原文核对状态字段，看它是工作草案／候选推荐／推荐标准，并记下是哪一份、什么状态、什么日期；② 到官方文档（MDN／web.dev 等二级资料）交叉核对，仍不能定则回到标准组织站点；③ 若不同来源冲突，写出冲突与各自出处，而不是挑一个。一级资料＝标准与规范原文（WHATWG Living Standard、ECMA 系列、IETF RFC、W3C 规范，注意其状态字段）。

**13** 根因与方向：① 行内 `style` 把表现写进结构——移入样式表；② `onclick` 行内事件把行为写进结构、且"点击查看"是假交互——导航用 `<a>`、动作用 `<button>`；③ `<b>` 与 `<br><br>` 用标签做纯视觉效果——改用 `<strong>`（若表语义强调）或去掉，换段用块级元素、间距交给 CSS；④ "最新通知"是标题却用 `<b>`——按层级改为标题元素；⑤ "点击查看"脱离上下文不可读——写清目标的链接文字。**指出 3 条及以上给满分。**

**14** 要点：请求头——`Host`、`User-Agent`、`Accept`、`If-None-Match`；响应头——`Content-Type`、`Cache-Control`、`ETag`（2 分）。可能得到 304（资源未变、无响应体）或 200（已变，重新返回正文）（2 分）。`ETag` 是服务器上次给的资源标识，浏览器下次请求把它放进 `If-None-Match` 回带，服务器据此判断是否 304——即"协商缓存"（2 分）。

**15** 验收判据（每项 2 分，满 10 分；可复现性 2 分）：语义元素使用正确（标题用标题元素、正文用段落）；图片有描述内容的 `alt`（不是文件名）；页面标题与内容一致；服务器绑定地址能对外（不只是 `127.0.0.1`），局域网另一设备确实打开（附截图）；提交物说明"为什么必须用服务器方式"。
**评分要点**：语义正确与替代文本质量（占主要）｜可复现性（别人照你的步骤能否做到）｜差异/原因说明。
**常见扣分点**：只写"能打开"不说机理；`alt` 抄文件名；服务只绑 `127.0.0.1` 却称"已发布"；无截图证据。

**16** 验收判据（每项 2 分，满 10 分；分级 2 分）：① 用 `curl`（或等价工具）抓到某页面的响应头并逐行列出；② 本地静态服务器复现同一请求；③ 两处头部逐行对照，标出"哪些一致、哪些不一致"（如 `Host`、`Date`、`Content-Length` 会不同）；④ 对说法"万维网是 1991 年由美国人发明的"给出判定（正确说法：1989 年 3 月由在瑞士 CERN 工作的 Tim Berners-Lee 提交备忘录，年份与国别均需出处）；⑤ 每条结论附来源与**来源分级**（一级规范／二级官方文档／三级教程／四级其他）。
**评分要点**：请求解剖准确性｜来源分级是否正确｜对来源冲突的处理是否如实。
**常见扣分点**：出现"网上说"而无出处；把年代或国别写错还不标来源；**编造来源本题直接 0 分**。

**17** 答案 **C**。要点：乱码主要由 `charset` 声明与编码不匹配造成，与 `lang` 无直接因果；`lang` 影响的是发音、断词、校对、翻译判断。

**18** 答案 **B**。要点：`id` 不参与提交；只有带 `name` 的控件才进入提交数据；`type` 也不是键名。

**19** 答案 **A**。要点：分节内容 = `article`、`section`、`nav`、`aside`（划定大纲层级）；B 是短语／流内容，C 是短语内容，D 是列表类元素。

**20** 答案 **B**。要点：一页通常一个 `<main>`，且应与 `header`/`footer` 同级、不含全站重复导航；"多个"违反本课程口径（规范不硬禁，但教学按"唯一"要求）。

**21** 答案 **C**。要点：装饰图写 `alt=""`（明确声明装饰、请辅助技术跳过）；省略 `alt` 可能被读文件名；`alt="分隔图"` 是无信息噪声。

**22** 答案 **D**。要点：`sizes` 描述不同视口下的占位宽度（CSS 像素），与 `srcset` 的 `w`（图片真实像素宽）配对；只写 `srcset` 缺布局信息，可能选到过大的图。

**23** 答案 **B**。要点：表头是 `<th>` 并配 `scope`；样式像不像表头不重要，语义才重要；`<caption>` 是表格标题，不是表头；`<thead>` 单独用不足以表达关联。

**24** 答案 **错误**。要点：容错修复按 WHATWG Living Standard 的解析算法进行，是规范规定的、可预测的，但**修出来的 DOM 常常不是你写的结构**（如 `<p>` 里进 `<div>` 会隐式闭合、表格内的 `<div>` 会被移出），而它正是 CSS 与 JS 的依据。

**25** 答案 **错误**。要点：`h` 表示大纲层级，不是字号；字号归 CSS。为了视觉大小挑 `h4` 会导致大纲跳级，破坏依赖标题导航的用户体验。教学口径为一页一个 `h1`、层级连续。

**26** 要点（每点 2 分；满分靠"两个理由 + 两个具体例子"）：理由——① 恢复行为虽可预测，但**不一定是你想要的结构**，会误导 CSS/JS 调试；② 其他消费方（非浏览器解析器、抓取器）容错能力不保证相同。具体例子——`<p>` 内遇块级开始标签会隐式闭合 `<p>`；`<table>` 内直接放非表格内容会触发 foster parenting 被移出表格；未闭合 `<li>` 遇下一个 `<li>` 自动闭合（举其中两个即可）。**只答"为了规范"不给分。**

**27** 要点（两处问题各 2 分、修复 2 分）：跳级（`h2`→`h4`）让依赖标题导航的屏幕阅读器与机器抽取方丢失结构连续性；多个 `h1` 让"本页主题"无法唯一识别。修复：层级改为连续（`h1`→`h2`→`h3`→`h4` 各就其位）、只保留一个描述本页主题的 `h1`、字号交给 CSS。

**28** 要点（结论 2 分，人工判断项各 2 分）：不能作达标证明。工具只能查规则化的项；人工判断项举例——`alt` 的信息是否等效、标题层级是否合乎内容逻辑、Tab 顺序是否与视觉顺序一致、表单错误提示是否清晰可达。要能区分"通过审计"与"真的能用"。

**29** 根因与改法：第二行更友好，因为 `alt` 承载了等效信息；第一行等于把文件名读给用户，信息量为零。改法——若图承载数据 → 写等效信息描述；若纯装饰 → 写 `alt=""`。**必须点出"信息来源不同、改法不同"。**

**30** 根因与工具：① 表头应是 `<th>` 并配 `scope`，否则单元格失去表头关联，读屏无法报出"列 X、行 Y"；② 非表格内容放在 `<table>` 内会触发 foster parenting，被浏览器移到表格外，结构被改写。观察工具：Elements 面板对比源码与 DOM（并排截图）。

**31** 验收判据（逐条 2 分，满 10 分；扣分项另计）：关闭 CSS 后整页可顺序读通、地标齐全、`<main>` 唯一、标题层级连续；图表 `alt` 为等效信息、纯装饰元素 `alt=""` 不产生噪声；表单每控件有 `label` 关联、有 `name`、`type` 与数据匹配，单选项有 `fieldset`/`legend`；通过结构校验器与浏览器无障碍审计（无自动可查问题）；链接文字脱离上下文仍可读懂。
**常见扣分点**：出现行内 `style` 或 `<table>` 排版（直接判不合格）；`placeholder` 顶替 `label`；`main` 出现多次；只勾清单不给证据。

**32** 验收判据（每项 3 分）：`srcset` 用 `w` 描述符且数值等于图片真实像素宽度；配有 `sizes` 描述布局占用宽度；切换视口宽度时 Network 面板显示实际下载文件变化；三张图 `alt` 分别符合"信息／装饰／功能"。
**评分要点**：`srcset`/`sizes` 是否配对（只写其一不通过）；`w` 是否写错成显示宽度；`alt` 场景判断是否准确。
**常见扣分点**：把 `w` 写成 CSS 显示宽度；装饰图写成信息图；省略 `sizes`。

### M3

**33** 答案 **B**。要点：普通声明下未分层样式优先级高于所有分层样式；分层设计的就是让"默认/库样式"可被业务样式覆盖。

**34** 答案 **C**。要点：三条均未分层、无 `!important`，比特异性——① `.a .b` =(0,2,0)、③ `.a.b` =(0,2,0)、② `#x .b` =(1,1,0)，id 一票最高，② 胜出。特异性三元组按(id, 类/属性/伪类, 元素/伪元素)比较、不进位。

**35** 答案 **D**。要点：`border-box` 下 `width` 即总宽（含 padding 与 border），所以是 200px；`content-box` 下才是 200+40+2=242px。

**36** 答案 **B**。要点：相邻兄弟垂直 margin 合并取较大值，非相加，故 40px。

**37** 答案 **A**。要点：`rem` 参照根元素字号，`em` 参照当前元素或父级字号。

**38** 答案 **D**。要点：`:is()` 特异性取参数中最高的；`:where()` 恒为 0，用来写"好被覆盖"的默认样式。

**39** 答案 **C**。要点：`flex: 1` = `flex-grow:1; flex-shrink:1; flex-basis:0%`。

**40** 答案 **B**。要点：`auto-fit` 折叠空轨道让项目拉伸铺满；`auto-fill` 保留空轨道、项目保持原宽。

**41** 答案 **C**。要点：动画优先 `transform`/`opacity`（可只走合成）；`outline: none` 会移除焦点可见性；`prefers-reduced-motion` 全局有效。

**42** 答案 **正确**。要点：`display: flow-root` 让父元素形成 BFC，阻断父子外边距塌陷；`overflow: hidden` 也能阻断但会裁剪需要溢出的子元素，故不首选。

**43** 答案 **正确**。要点：移动优先即默认样式写给窄屏，再用 `min-width` 往上叠加，覆盖链更短、更好维护；`max-width` 是桌面优先思路。

**44** 要点（结论 3 分、链条 3 分）：最终 **C**。链条——三条均为普通作者声明、无 `!important`，先比层序：① 与 ③ 未分层，② 在 `@layer components` 层内，未分层样式优先于分层样式，故 ② 先被淘汰（尽管其特异性最高）；① 与 ③ 之间再比特异性，③ `#app.container .btn` 高于 ① `.btn`，③ 胜出。**必须能说清"层序先于特异性比较"。**

**45** 要点（现象 2 分，两种办法各 1.5 分）：现象——块级正常流里，父子之间首/末个子元素的垂直 margin 会"溢出"到父元素外，与父元素 margin 合并。阻断办法——① 父元素建立 BFC（如 `display: flow-root`），边界清晰、不裁剪内容；② 给父元素加 `padding` 或 `border` 隔开；边界说明：`overflow: hidden` 虽也能阻断，但会裁剪需要溢出的子元素（如浮层），不宜作为首选；Flex/Grid 子项本身不塌陷。

**46** 要点（规则 2 分，三参数各 1 分）：形如 `clamp(16px, 2.5vw, 24px)`（数值可不同，只要满足下界与上界）。三参数：最小值、首选值、最大值——浏览器取三者的中间被夹紧结果；夹紧后不小于 16px、不大于 24px、中间段随视口变化。

**47** 要点（归位 3 分，两轴 2 分）：容器属性——`justify-content`、`align-items`、`flex-direction`；子项属性——`align-self`、`flex-basis`、`order`。`justify-content` 管主轴分布，`align-items` 管交叉轴对齐（`flex-direction` 改变的是哪条轴是主轴）。

**48** 要点（真因 3 分，改法 3 分）：真因——`transform` 非 none 会在 `.wrap` 上创建新的**层叠上下文**，内部浮层的 `z-index: 9999` 只在这个上下文内比大小，与被 `.wrap` 分隔在不同上下文里的同级浮层无法直接比较。改法——① 去掉 `.wrap` 上非必要的 `transform`（或改用不创建上下文的属性）；② 调整结构，让两个要比较的浮层处在同一层叠上下文内（例如把浮层提升到 `body` 下的共同容器）。先查层叠上下文，再谈数值。

**99** 验收判据：① 容器上的监听器数量为 1（可用 Elements → Event Listeners 面板自测）；② 动态追加的条目点击有效、无需重新绑定；③ 点击条目输出其 id，点击空白区域不产生输出；④ 嵌套子元素（如条目内删除按钮）点击时能被正确归因到所属条目；⑤ 列表移除后监听器随之释放（面板计数归零）。
**评分要点**：委托目标定位（`closest`）稳妥、未误把容器自身当条目（30%）｜动态追加项验证（20%）｜嵌套子元素归因（20%）｜解绑与生命周期处理（20%）｜不引入 `stopPropagation` 之类的掩盖手法（10%）。
**常见扣分点**：在回调里直接用 `event.target` 而不 `closest`；未校验目标是否在容器内；忘记解绑；用 `stopPropagation` 掩盖问题。

**100** 验收判据：① 计算运行期间点击按钮无卡顿，Performance 面板 Main 轨道上不再出现该段长任务；② 输入与输出通过 `postMessage` 传递，结果与主线程计算一致（同输入同输出）；③ 错误路径有处理——Worker 抛错或加载失败时页面给出可见提示、不静默失败；④ 页面卸载或重复触发时旧 Worker 被终止（不残留多个运行的 Worker）；⑤ 说明 Worker 内为何不能直接操作 DOM。
**评分要点**：长任务是否真的从主线程消失（35%）｜结果一致性验证（20%）｜错误与终止处理（25%）｜对"Worker 无 DOM"的解释（10%）｜无"留全局引用导致 Worker 无法回收"的写法（10%）。
**常见扣分点**：只把计算放进 Worker 却仍在主线程同步做一遍；无错误处理、加载失败静默；每次触发都新建 Worker 却不终止旧的；把 DOM 操作写进 Worker 导致报错。

## 八、易错题与阅卷提示

1. **第 3、9 题（URL 片段）——全班性易错点。** 学生普遍认为 `#` 之后的参数会发给后端。判分口径：只要答出"片段不参与请求、供浏览器内部跳转"即得分；答"查询串不发送"判错。若学生额外指出"用哈希路由/框架路由时片段仍不发给服务器"，加分不扣分。

2. **第 17 题（`lang` 与乱码）** 是典型"字面像对、机理不对"的题。乱码的根因是 `charset` 与编码不匹配，与 `lang` 无因果。判分口径：选 C 得分；若学生辩解"没有 `lang` 浏览器也可能误判编码"，须在评语中说明"教学口径以 `charset` 为准"，不因该辩解改变答案，但可在解析要点上给其半句认可。

3. **第 33、44 题（`@layer` 与未分层）** 学生常按"后写的赢"或"特异性高者赢"作答，忽略"未分层样式优先于所有分层样式"和"层序先于特异性比较"。判分口径：结论错即该题不得分，但若结论对、链条缺"层序先于特异性"这一步，扣一半；能写出比较链条的给满分。

4. **第 40、51 题（`auto-fit` / `auto-fill`）** 只答"一个会折叠、一个不会"得一半分；必须说清后果（项目被拉伸铺满 vs 右侧留空）才给满分。

5. **第 55、56 题（`==` 转换链）** 单选答案一致，但要求"说明转换链"。判分口径：只写答案得基础分，能写出 ToPrimitive / 数字转换链才给满分；对 `[] == ![]` 给出"两边都变 0"的解释即算到位。

6. **第 73 题（循环里 `var` 的闭包）** 部分学生写 `[0,1,2]`。判分口径：结论错但能给出"改用 `let`"的改法，改法分照给；结论错且解释成"闭包复制了值"的，改法与解释均不给分。

7. **第 96 题（输出顺序）** 易错在 D 的执行时机——D 是 C 的 `.then` 里新排入的微任务，须在本轮微任务清空时一并执行，故在 E 之后、B 之前。判定以 `A、F、C、E、D、B` 为准；若把 D 排到 B 之后判错。理由中须体现"微任务本轮清空"。

8. **第 87、88 题（存储与 Worker）** 两个判断题都是"想当然"型。判分口径：只写"正确/错误"不得分，必须给出理由；第 87 题理由须点"sessionStorage 生命周期绑定当前标签页"；第 88 题理由须点"Worker 无 DOM、靠 postMessage 通信"。

9. **编程题（15、16、31、32、53、54、77、78、99、100）的统一口径。** 一律**只按验收判据判分，不比对实现写法**——只要达判据即满分，不因"与教师思路不同"扣分。**出现性能/安全红线的一律按判据扣分或判不合格**：M3 第 53 题卡片墙写了 `@media`（一票否决）；M1 第 16 题编造来源（直接 0 分）；M2 第 31 题出现行内 `style` 或用 `<table>` 排版（不合格）；M4 第 78 题 `debounce` 丢 `this`（扣透传分）。

10. **不得因措辞不同扣分的情形。** 以下情形表述与学生用词不同，意思一致者同等给分：① 把"层叠上下文"说成"独立的比较作用域"；② 把"外边距塌陷"说成"margin 合并"；③ 把"暂时性死区"说成"TDZ / 声明前不可访问"；④ 把"渲染树"说成"布局树"（本课程统一用"渲染树"，但理解正确不因术语差异扣分）；⑤ 把"合成线程"说成"compositor"；⑥ 把"事件委托"说成"事件代理"。反之，**术语写对但机理说错的，按机理分扣**。

11. **争议题判分口径——第 20、25 题（`<main>` 唯一性、一页一个 `h1`）。** 规范并未硬性禁止多个 `<main>`、多个 `h1`，本课程按"唯一/一个"提出教学口径（见 [[02-教案 M2 HTML 与语义化]] 第 9 节）。判分口径：按本课程口径判正确；若学生答"规范不禁止但本课程按唯一要求"，视为完全正确并给满分；不得因学生指出"规范允许"而扣分。

12. **证据类扣分（跨模块统一）。** M1 第 15、16 题、M2 第 31 题、M3 第 49、53 题、M5 第 95、99、100 题要求"可复现证据"。判分口径：结论正确但无证据（工具截图、改前/改后数字、复现步骤），该项按 [[13-考核方案与评分量规]] 的"证据不足"处理，最多给该项一半分；出现"感觉快了""网上说"一类措辞的，该项不得分。
