## M1 · Web 的起源与技术基础

> 并入自 48 学时版本《Web 网页技术》01-教案 教案

### 教学重点与难点

**重点**
1. 结构 / 表现 / 行为三分法，以及「分离」带来的真实好处（可维护、可访问、可协作）。
2. 五个演进阶段的**驱动力**：为什么每次变化都不是「技术炫技」，而是被需求逼出来的。

**难点**
1. 学生普遍把「学会用框架」当成学 Web 的目标——本章要打掉这个预期，但不能变成说教，要靠**让他们看到框架解决的是第 5、6 阶段的问题**。
2. 「语义化」「分离」这类价值观，讲道理没用，要靠反例：给一段用「表格布局 + 一堆 div」写的页面，让他们关掉 CSS 看还剩什么。

**突破策略**：全章用**同一个页面**（校园社团主页）在五个阶段下的不同写法贯穿演示，学生能直观看到「同样一个页面，写法换了几次」。

### 教学准备（环境与教具清单）

### 课程思政融入点

1. **开放共享的技术精神**：CERN 在 1993 年宣布 Web 技术**免版税开放**，Berners-Lee 与 W3C royalty-free 的路线选择，是 Web 能成为公共基础设施的根本原因。对比同期若干私有网络服务的失败，说明**开放标准**的分量。
2. **中国接入与自主创新**：1994 年 4 月，中国实现与国际互联网的全功能 TCP/IP 连接，此后三十余年从"接入者"变为"建设者"——移动支付、小程序生态、跨境电商成为世界上独特的实践。技术主权意识从这里起步。
3. **规范的公共责任**：无障碍（Accessibility）不只是一项技术要求，它决定了视障用户能不能用你做的页面。**写代码的人有社会责任**，这一点在第 2 章会再具体展开。

### 课后作业与预习

**作业（计入平时成绩，下次课交）**
1. 打开任意一个你常用的网站，用「查看源代码」和开发者工具（「查看源代码」= 页面右键 → 查看网页源代码，或 `Ctrl+U`；开发者工具 = `F12` 或 `Ctrl+Shift+I`，**Elements** 看结构、**Sources** 看行为），写出**三句话**：哪部分属于结构、哪部分属于表现、哪部分属于行为。要求举出具体的标签或类名作为证据。
2. 访问 [info.cern.ch](https://info.cern.ch/)，看世界第一个网站，写 150 字观察：它有什么、没有什么（提示：注意有没有样式、有没有图片）。
3. 不看讲义，用自己的话写出五个阶段的**驱动力各是什么**（只写驱动力词，不写年份）。

**预习（下次课为第 2 章 HTML）**
- 通读 [MDN 学习区](https://developer.mozilla.org/zh-CN/docs/Learn_web_development) 的 `Core/Structuring_content/Basic_HTML_syntax` 一节
- 预习问题：「如果不写 `<!DOCTYPE html>`，浏览器会怎么办？为什么它可以不写也能显示？」

## M2 · HTML 与语义化

> 并入自 48 学时版本《Web 网页技术》02-教案 教案

### 教学重点与难点

**重点**：① 语义化标签的实际收益；② 元数据区的必写项；③ 表单与无障碍。
**难点**
1. **「能显示」与「写对了」的分离**——浏览器有容错解析，错误 HTML 照样渲染。必须让学生亲手看到 `p` 里塞 `div` 被浏览器"踢"出来。
2. **语义化的收益不可见**——页面看起来一模一样。突破手段：用浏览器"阅读模式"和屏幕阅读器模拟（Chrome 的 Accessibility 面板：`F12` → **Elements** → 选中元素 → 右侧 **Accessibility** 标签，可看地标与无障碍名，参考 [MDN 无障碍模块](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Core/Accessibility)）当场对比语义页与 div 页。
3. 表格只用于数据这个界限，学生容易为了省事又回到表格布局。

### 课程思政融入点

**无障碍就是社会公平的技术实现**。中国有超过 1700 万视障人士，他们用读屏软件上网。一个语义正确的页面，读屏能把"导航、主体、页脚"念清楚；一个全是 `div` 的页面，他们只能听见一片噪声。这件事的代价对学生是"多打几个字"，对使用者是"能不能用"。**写代码的职业伦理，从 `alt` 和 `label` 开始。**

### 板书设计

```
结构三问：
  1. 这个东西是什么？      → 选语义标签
  2. 它有什么信息？        → 属性（alt / label / scope）
  3. 它属于哪一块？        → 地标（header nav main article section aside footer）

去掉 CSS，还读得通吗？ ← 本章唯一硬标准
```

### 课后作业与预习

**作业（与实验 2 配套，计入平时成绩）**
1. 手写一份个人主页 HTML（**不写一行 CSS**）：`header` + `nav` + `main`（含 3 张卡片用 `article`）+ `aside` + `footer`；一个 6 字段表单（文本框、email、下拉、单选或多选、多行、提交按钮），每个控件 `label` 正确关联；一张数据表格（≥4 行 3 列，`thead` + `th` + `scope`）。
2. 把作业提交到 W3C 校验器（打开后把 HTML 粘进 **Check** 页，或上传文件），**截图校验结果**；若有报错，写下你改了哪几处、为什么。
3. 反例分析：找一个真实现网的某个区域，写出「它是用 div 堆的，如果改语义标签应该怎么改、为什么」。

**预习（第 3 章 CSS）**
- 通读 [MDN CSS 参考](https://developer.mozilla.org/zh-CN/docs/Web/CSS/Reference) 的 `Web/CSS/Guides/Cascade`（层叠与优先级）与 `Web/CSS/CSS_box_model`（盒模型）
- 预习问题：「我给一个元素设了 `width: 200px; padding: 10px; border: 1px solid`，它实际占多宽？为什么？」

## M3 · CSS 与布局

> 并入自 48 学时版本《Web 网页技术》03-教案 教案

### 教学重点与难点

**重点**：① 层叠与优先级；② 盒模型（尤其 `box-sizing`）；③ Flex 与 Grid 的最小可用集；④ 响应式三件套。
**难点**
1. **外边距塌陷**——学生最难接受的一点：两个 margin 不是相加，是取大。
2. **Flex 与 Grid 的选择**——需要反复用"一维还是二维"这个判据，最好用同一张设计图做两种实现对比。
3. **`position` 与文档流的关系**——`absolute` 脱流后"谁给谁当参照系"最容易混。
4. 学生习惯「试到看起来对」，不愿打开开发者工具。**本章要强制建立这个反射**。第一步固定动作：`F12` 打开、`Ctrl+Shift+C` 点选元素，选中后右侧 **Styles** 看哪条规则胜出、被谁划掉。

### 课程思政融入点

**"可维护"是一种职业素养**。本章反复出现的一个要求是"让别人改得动"：用变量而不是到处写死色值，用 `gap` 而不是到处调 margin，用层级而不是堆 `!important`。工程里的潦草不是能力问题，是**对后来者的态度问题**——包括半年后的你自己。团队协作中，一个人图省事写的 `!important`，会让三个人多花一天。

### 板书设计

```
层叠四问：来源 → 层 → 特异性 → 顺序          ← 谁赢
盒模型：  content │ padding │ border │ margin  ← 多大
布局二选：一维 Flex ｜ 二维 Grid              ← 怎么排
响应三件：viewport + 相对单位 + (Flex|Grid 或 媒体查询)

不生效 → F12（第一步，不是最后一步）
```

### 课后作业与预习

**作业（配合实验 3、4，计入平时成绩）**
1. 复现并解释：写一段代码让**外边距塌陷**发生，再写三种不同的修复方式，比较各自副作用。
2. 用 Grid 复刻一张卡片网格：窗口宽度变化时 1 → 2 → 3 列自动切换，**不允许写任何媒体查询**。
3. 用 CSS 变量 + `prefers-color-scheme` 实现全站深浅色，要求**所有颜色都走 `var(--…)`**，切换后不出现漏色的元素。
4. 反例分析：找一个真实现网，用开发者工具（`F12` → **Elements** → 选中元素 → **Styles** 面板搜 `!important`，行内样式直接看 `style` 属性）找出**一个用 `!important` 或行内样式解决覆盖问题**的地方，写出"按本课方法应该怎么改"。
5. 用五步定位法，记录一次你自己的"样式没生效"排查过程（写清每一步看到了什么）。

**预习（第 4 章 JavaScript）**
- 通读：[现代 JavaScript 教程（中文）](https://zh.javascript.info/first-steps)（语言基础部分）
- 预习问题：「`var`、`let`、`const` 三者的区别是什么？为什么现在推荐 `const` 优先？」

## M4 · JavaScript 语言核心

> 并入自 48 学时版本《Web 网页技术》04-教案 教案

### 教学重点与难点

**重点**：① 数组方法（`map/filter/reduce`）；② DOM 操作与类名切换；③ 事件委托；④ Promise 与 `async/await`。
**难点**
1. **`this` 的绑定**——四种规则，学生只记住"箭头函数没有自己的 this"往往仍会写错。
2. **异步的执行顺序**——同步代码执行完才轮到微任务，学生的直觉普遍是"写了就先执行"。
3. **引用类型的赋值**——对象变量存的是地址，改`副本`会影响原对象。
4. **`innerHTML` 的安全与性能**——学生最爱用它，本章要给出正确做法（第 5 章讲 XSS 时收口）。

**突破策略**：异步部分用**同一段逻辑写三遍**（回调嵌套 → Promise 链 → `async/await`），让学生亲眼看到可读性差异；再画一张"调用栈 + 微任务队列"的顺序图。

### 课程思政融入点

**"能跑"和"对"之间的距离，是专业性的体现**。本章大量错误都属于"页面看起来正常，但代码是错的"：`==` 碰巧相等、`innerHTML` 碰巧没被注入、`fetch` 碰巧返回 200。这类代码在真实系统的某个边界上一定会出事——而那时付出的代价由别人承担。**写代码时假设"输入是恶意的、网络是不可靠的"，这不是偏执，是责任。**

### 板书设计

```
JS 执行顺序：同步 → 微任务(Promise) → 宏任务(定时器/事件)

this 四问：谁调用的？ / 箭头？ / bind? / new?
异步三写：回调 → Promise → async/await   （同一件事写三遍）

DOM 口诀：选取 → 改内容 → 开关类名（不是改 style）

fetch 三坑：不 reject 4xx / 要 await 两次 JSON / 无超时
```

### 课后作业与预习

**作业（配合实验 5、6，计入平时成绩）**
1. 用 `map` / `filter` / `reduce` 完成：把一组学生成绩对象，筛出及格的、换成百分制、求平均分与最高分（**每题只允许一条链式表达式**）。
2. 写一个待办清单（原生 JS 版）：增、删、勾选完成、计数、清空；用**事件委托**处理所有按钮；用类名切换样式。
3. 写一个函数 `fetchWithTimeout(url, ms)`，用 `Promise.race` 或 `AbortController` 实现超时。
4. 用 `fetch` 拉一个公开接口的数据渲染成列表，**必须有加载中、成功且有数据、成功但为空、失败四种状态**（失败要有重试按钮）。**注意区分「空态」与「失败态」：空态是请求成功但结果为 0 条，失败态是请求出错——两者界面要长得不一样，不能都只显示「没有数据」**。
5. **调试题**：下面这段代码为什么拿不到数据？写出你的排查过程（不是只写答案）。可先按 `Ctrl+Shift+J` 在 **Console** 里直接跑一遍看结果，再用 **Sources** 面板断点单步验证（`F10` 跳过、`F11` 进入、`F8` 继续）。
   ```js
   const data = fetch('/api/x').then(r => r.json());
   console.log(data);
   ```

## M5 · 浏览器原理与运行时

> 并入自 48 学时版本《Web 网页技术》05-教案 教案

### 教学重点与难点

**重点**：① 渲染路径与三类脚本执行时机；② HTTP 请求响应与状态码；③ 跨域与缓存（实际开发中最常撞的两堵墙）。
**难点**
1. **渲染路径的因果推论**——学生能背出"DOM → CSSOM → 渲染树"，但用不出"所以动画要用 transform"。要靠**对比实验**（改 `width` vs 改 `transform` 看 Performance 面板）建立。
2. **CORS 的报错信息有歧义**——浏览器只说"被 CORS 阻止"，却不说服务端到底缺哪个头。要教学生**先看 Network 面板里那个 `OPTIONS` 请求**。
3. **缓存导致"我改了但没生效"**——必须教会用 `Ctrl+Shift+R`（或 `Ctrl+F5`）强制刷新与 Network 面板的 "Disable cache"（`F12` → **Network** → 勾 **Disable cache** 并保持面板打开；先开面板再按 `Ctrl+R` 记录一次重载），否则后面每章都会被这个问题绊住。

### 课程思政融入点

1. **网络安全是国家安全的一部分**。本章的 XSS/CSRF/HTTPS 看着是技术细节，实则是数据安全与个人隐私的底线。中国《网络安全法》《数据安全法》《个人信息保护法》对数据收集与传输都有明确要求——**做前端的第一个合规动作，就是不要把用户输入当代码执行**。
2. **不放开后门图省事**。学生学完 CORS 最想干的事是"装个关跨域的插件"。要在这个点上明确态度：解决办法是**理解并正确配置**，不是绕过机制。技术人的底线往往体现在这种"小地方"。

### 板书设计

```
HTML→DOM ┐
         ├→ 渲染树 → Layout → Paint → Composite
CSS →CSSOM┘

改 width/height → Layout（贵）
改 color        → Paint
改 transform    → Composite（便宜）

同步 → 微任务 → 宏任务        （与第 4 章呼应）

同源 = 协议 + 域名 + 端口
4xx 我错 / 5xx 他错
强缓存不发请求 / 协商缓存问一句(304)

XSS：用户输入当代码执行 → textContent
CSRF：浏览器自动带 Cookie → SameSite
```

## M7 · 组件化与框架

> 并入自 48 学时版本《Web 网页技术》07-教案 教案

### 教学重点与难点

**重点**：① 组件化思维（拆分与通信）；② 响应式数据与"不要直接改 state"的真正含义；③ 路由；④ 状态该放在哪一层。
**难点**
1. **"为什么不要直接改 state"这句话的适用条件**——这是最容易被教错的地方。**React 里必须用 `setState` 因为直接改不会触发重渲染；Vue 里直接改 `ref.value` 是完全可以的**，因为响应式系统通过 Proxy 追踪了修改。学生把 React 的规则当成普适真理，是最常见的错。
2. **组件拆分的度**——拆太细 props 传递地狱，拆太粗失去复用。要给出判据而非口号。
3. **路由的手写感**——单页应用里"换页不刷新"是反直觉的，要讲清 History API 与浏览器历史栈的关系。

**突破策略**：用**同一个待办清单**贯穿两次课——先用原生 JS 写（第 4 章作业已写过），再用组件化写。让"框架省掉了什么"变成可对比的事实。

### 课程思政融入点

1. **中国开源力量**。Vue 由尤雨溪（中国开发者）创造，Vite 同样出自他主导的团队，至今是世界范围内使用量最大的前端框架与构建工具之一。**技术影响力来自解决真问题，而不是来自地域**。学生不必把"用国产技术"当口号，但应该知道这条线上有中国人的贡献。
2. **技术选型要负责**。框架选型关系到团队未来数年的维护成本。"这个火所以用"不是理由，第 4.8 节给的三条边界就是选型的底线思维——**能少则少，能用简单的就别上复杂的**。
3. **对本课程前六章的呼应**：框架跑得再远，也跑不出结构、表现、行为、网络、工程这五件事。**基础扎实的人换框架成本很低；只学框架的人换一次框架就要重学一次。**

### 板书设计

```
命令式：怎么做（改 DOM 的一串动作）      → 忘记同步
声明式：是什么样（数据 ↔ 界面 的对应）   → 框架负责同步

Vue   ：Proxy 拦截修改 → 自动更新
React ：必须换新引用  → 才触发更新     （不同机制，别互套规则）

组件通信：props 下传 / 事件上抛 / 插槽管内容
状态归属：本地 → 提升 → 全局（按需，不滥用）

路由：单页不刷新 = History API
       history 刷新 404 → 服务端回退 index.html

渲染：CSR / SSR / SSG / ISR  → 取舍，不是优劣
```
